# 方法与实验设计

[项目首页](../README.md) · [统计方法](benchmark-methodology.md) · [功能验证](validation-report.md)

主题：**面向动态形状算子的分层Java编译、窗口复用估计与有限缓存派发。**

## 执行层次

参考解释层逐节点计算；通用层覆盖合法N/D；专用层使用精确或二维区间守卫。矩阵乘法另有明确的N/K/M输入和独立CPU编译入口。动态图、融合、形状守卫与编译API均有已有研究基础，项目不将这些概念声称为原创发明。

## 形状族与复用估计

N可采用二次幂或固定跨度，D可固定或采用固定跨度。当前输入进入相应形状族后，窗口保存最近W个请求，统计该族频率f。预测复用数H=f×预测请求预算，取代永久seen乘数。

在热点阈值、专用编译软预算和预期回收条件满足时建立候选。编译前以通用计算时间10%作为潜在节省启发式；编译后执行交错A/B测量，专用至少快2%且H能够回收编译成本才接纳。周期复核测到超过通用5%的退化或异常时撤销。

这些是显式策略阈值，不知道实际请求会如何变化，不构成在线最优证明。软预算只控制编译准入，单次已开始编译可超过剩余预算。探测和复核成本计入触发请求。

## 可检验问题

| 问题 | 对照 | 观察值 |
|---|---|---|
| 融合是否抵消冷编译成本 | INTERPRETED / GENERIC | 冷请求、测量期请求、计算时间 |
| 扩大形状族是否减少编译 | EXACT / BUCKET，不同N/D跨度 | 编译数、淘汰与守卫命中 |
| 窗口是否反映分布变化 | 实测轨迹、分布切换、不同W | 过期热度、频次、准入事件 |
| 自适应探测是否值得 | BUCKET / ADAPTIVE | 探测开销、接纳/拒绝、P95 |
| 组合行阶段是否正确 | 手算方差/Softmax、参考解释器 | 输出形状、全量数值与边界 |
| 分块矩阵代码是否有效 | REFERENCE / GENERIC / BLOCKED | 冷成本、计算分位数、跨fork区间 |

## 输入与控制

真实特征流使用三套完整公开数据；实测形状轨迹从这些完整运行的逐批日志提取；合成轨迹则用于控制热点、长尾、宽度变化与分布切换。来源、内容和值生成方法分开记录。

每种策略/每个fork是独立JVM。轮换执行顺序减少固定先后偏差；保留应用、DSL、数据摘要、JDK、系统参数和所有原始输出。跨fork统计使用进程级样本；系统噪声只作诊断，不自动剔除慢进程或宣称因果。

矩阵乘法的分块与参考都按K递增累加，不改变求和关联；使用手算样例、余数块、三轴越界、非有限值和别名限制验证。当前范围是CPU/double，不将结果推广到GPU、完整深度学习模型或生产吞吐。
