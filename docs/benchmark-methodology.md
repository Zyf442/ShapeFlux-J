# 实验计时、置信区间与噪声

[返回首页](../README.md) · [验证记录](validation-report.md)

## 独立实验单位

bench、dataset与matmul都为每种策略、每次fork启动独立JVM，默认工作进程堆上限768MiB。各fork原始记录保留，轮换策略执行顺序。fork上限10；本包的重复实验使用5。

bench逐批按固定种子重建相同输入，区分cold、warmup和steady；生成输入与外部参考不计入引擎时间，但会影响进程分配/GC。dataset从同一真实文件开头完整或限行遍历，没有额外预热。matmul使用同一A/B输入快照，区分冷请求、预热和测量。

## 时间边界

| 指标 | 包含 | 排除 |
|---|---|---|
| 引擎完整请求 | 派发、输出分配、计算、触发的编译、内部验证、探测/复核 | 输入读取/生成、外部参考、JVM启动 |
| 内核计算 | 选中内核或参考路径计算 | 输出分配、编译、调优、外部参考 |
| dataset遍历总计 | 读取、摘要、引擎、外部参考、逐批记录与进度写入 | JVM启动、初始化、最终报告 |
| 系统诊断范围 | 该工作进程代码记录的整体范围 | JVM启动，范围边界见system-metrics.properties |

固定预热次数不保证JIT已稳定；异形状混合分位数反映这条轨迹，不当作单个固定形状的服务延迟。

## 95%均值置信区间

先分别得到每个独立fork的统计量，比如其计算中位数或引擎累计时间；再对这些fork级数值求均值、样本标准差s，并使用：

`mean ± t(0.975,n−1) × s / sqrt(n)`。

独立样本量n是fork数，不能把同一JVM的请求数当成n。只有一个fork时，标准差、区间与CV留空。区间估计的是fork统计量的均值，不是“95%请求落入的区间”。采用近似独立、适合t方法的假设，小样本、偏斜与共享机器干扰会限制解释。

实现为1～10个fork使用df1～9的t临界值。下界不截断；可能出现负下界，表示估计不确定，不代表运行时间为负。CV为s/abs(mean)，≥10%仅标记波动较大；任何慢结果都保留。

报告保留单forkP50/P95、跨fork均值区间、`confidence.csv/json`，以及逐请求或逐批CSV。统计公式依据[NIST](https://itl.nist.gov/div898/handbook/eda/section3/eda352.htm)。

## GC、JIT和CPU

每个工作进程记录GC次数与耗时增量、JIT编译耗时增量、进程CPU增量、测量范围墙钟时间、结束时堆使用量和系统负载平均值。平台不支持的字段标为unsupported，不填0冒充测量。

诊断范围包含预热和外部参考等工作，不能直接把全部GC/JIT耗时归给引擎。结束时堆用量不是峰值或RSS，`-Xmx768m`也不是内存实测。noise.csv给出每个进程的原始诊断，CV提示只描述观测波动，不证明原因。

## 输入一致性与状态

真实数据源文件在各工作进程前后核对SHA；特征流另有 `input_values_sha256`，父进程要求各策略一致。矩阵实验核对两个输入快照的摘要；轨迹分析保留原始与规范化CSV及来源摘要。

失败与取消保留metadata和已完成记录。只有全部工作进程成功并完成校验后，父进程标记COMPLETE并生成完整汇总。负向发布检查中的FAILED/CANCELLED是刻意测试的状态，不当作性能结果。
